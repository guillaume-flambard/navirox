# Adoption and community

This document is about earning useful public feedback while Navirox is
pre-alpha. It contains no sales forecast, pricing plan, or claim that a public
benchmark is a prospect.

## What to show

Each public demonstration should answer four questions:

1. What exact input was used?
2. What did Navirox produce or refuse?
3. How can another developer reproduce the result?
4. What remains unproved?

The best current demonstrations are bounded source analysis, the Vue transform
and refusal fixtures, provenance output, and the native runtime journeys. They
must remain separate because they prove different layers.

## Who can contribute

- Framework specialists can improve an adapter without changing the neutral
  planner.
- Mobile engineers can strengthen the target and runtime evidence.
- Tooling contributors can improve provenance, reproducibility, and reports.
- Product and design contributors can make refusal and uncertainty easier to
  understand without making them sound like success.

Contribution paths are described in [CONTRIBUTING.md](../CONTRIBUTING.md).
Maintainers should create small labelled issues before actively inviting new
contributors to a workstream.

## External repositories

Public applications may be pinned as benchmark inputs when their licence allows
the intended analysis. A benchmark is not a customer, partnership, endorsement,
or permission to reuse a product's branding, assets, credentials, or data.
Public output should describe the technical shape being tested and link the
input revision.

The historical benchmark selection note is in
[research/mobile-companion-targets-2026-09.md](research/mobile-companion-targets-2026-09.md).

## Publication gate

A public preview should wait until a new user can follow one documented install
and analysis path without private infrastructure or unpublished dependencies.
Until then, link to the source checkout instructions and state the registry
boundary in the opening section.

Public npm release, security-alert triage, repository settings, and external
communication remain explicit maintainer actions.

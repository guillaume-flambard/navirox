Three defects had to be fixed before a capture existed, all recorded here because each one is a property of the pipeline rather than of the fixture: the synchronous device spawn needed a raised `maxBuffer` (`DEVICE_OUTPUT_LIMIT_BYTES`, an Xcode build prints tens of megabytes and the default buffer kills the child with `ENOBUFS` instead of reporting the build error); the prepared application's `node_modules/.bin` had to be added to the environment the driver hands to Detox, because Detox runs the harness `start` command through a shell and `react-native` was otherwise not found; and the CocoaPods step (`installIosPods`, shared with `scripts/e2e-scaffold.mjs`) had to run before the build, because the scaffolded application ships a `Podfile` and lockfile but no `Pods` directory.
- [x] 3.2 Capture the motion scenario on the same path so the five temporal labels are produced on a device as they already are on the web. Verify the run report lists `rest, first-meaningful, midpoint, settled, interrupted` in order and that coincident frames are reported with a shared hash rather than hidden.

  The same command run without `--scenario` captures both scenarios and writes `docs/evidence/records-native-capture-records-motion-ios.json`, which lists `rest, first-meaningful, midpoint, settled, interrupted` in order with `labelsInOrder true`, one frame per label (rest 82478 bytes, first-meaningful 92911, midpoint 90803), and `Coincident frames: midpoint and settled and interrupted` carrying the shared hash `e3fceffb00d6d9fc6fa6ddcdad9146be27f517466e0fbe5ec0d859cd6aa23cae`. The coincidence is reported rather than hidden because the fixture is a discrete state machine: the settled frame presses the already-selected row and the interrupted frame replaces a pending selection, so both land on the same state as midpoint, and the report names the frames that share a hash instead of presenting three states as three distinct measurements. Driving the declared actions on a device exposed two real defects. First, `element(by.id(...))` cannot address an identifier that appears more than once: Detox refuses a matcher that matches several views, so `first-meaningful` and `interrupted` (whose first action carries no `nth`) failed with `Multiple elements found` while `midpoint` and `settled` passed; the harness `target` helper now always indexes (`atIndex(action.nth ?? 0)`). Second, the generated screen crashed at mount on iOS with `Text string "Alpha" must be rendered inside a <Text>`, because the benchmark fixture put bare text inside a `pressable`, which the safe subset accepts and the compiler emits as code that throws on a device. That is a target compiler gap and it is outside this change's declared impact, so the fixture was corrected (`<span class="row-button-label">` and `<span class="retry-label">`) and the gap is recorded in the evidence document as a discovered defect with its reproduction instead of being absorbed here. Regenerating the emitted file moved the recorded manifest hash from `4e556ef30b20b25aa3d41209e26e4c4bf492cc2f750752760038704e0394002a` to `e18712f368212b2481a868a3e6fa3fd5e42a58449fc099e1f503648b7eab4c48`; `pnpm --filter @memolabs-apps/target-vue test` passes with `Tests 10 passed (10)`, since the fixture test recompiles the source and compares bytes and manifest.

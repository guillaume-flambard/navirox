# Workflow value evidence

## Why

A companion can pass a device journey yet solve an unimportant mobile problem or
offer no material advantage over a PWA, WebView, or Capacitor. The current proof
backlog selects a bounded workflow from source findings, but it does not require
an explicit value hypothesis, an alternative-path decision, or validation with
the people expected to perform the work.

## What changes

- Define a reusable, evidence-led workflow-selection record for proof journeys.
- Require each selected workflow to state its actor, context, trigger, desired
  outcome, measurable friction, and desktop-only remainder.
- Require a documented native-versus-PWA/WebView/Capacitor decision based on
  the workflow, rather than an assumed superiority of native UI.
- Define how limited practitioner feedback may validate or reject the workflow
  without collecting credentials, customer data, or implying a customer
  relationship.

## Capabilities

### New Capabilities

- `workflow-value-evidence`

### Modified Capabilities

- None.

## Impact

- Proof planning, fixtures, and commercial qualification documentation.
- No product analytics, real user study, outreach, connector, or native UI is
  created by this proposal alone.
- The Baserow and SuiteCRM benchmark boundaries remain unchanged.
